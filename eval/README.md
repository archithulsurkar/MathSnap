# Benchmark

A labelled set of formula images with ground-truth LaTeX and, where it has been
confirmed, a screen-reader-validated spoken form.

## Why this exists

Maths-OCR benchmarks exist — im2latex-100k, CROHME for handwriting — and they
all measure the same thing: does the predicted LaTeX match. None of them measure
whether the *accessible output* is usable, because until recently nobody was
generating it at scale.

That is the gap this set fills. An entry carries the LaTeX, and it carries the
spoken form that a person who reads with a screen reader confirmed they could
follow. The second field is slow to produce and is the reason the set is worth
building: it cannot be generated by prompting harder.

## Running it

```bash
npm run eval                      # whichever backend PROVIDER selects
npm run eval -- --provider ollama # a specific one
npm run eval -- --limit 20        # a subset, while iterating
```

Output is a per-category table and `eval/report.json`. Entries whose image is
missing are skipped and reported as pending, so the harness runs before the set
is finished.

## What is measured

**exact** — the published number. Both sides are converted to MathML and reduced
to a canonical tree, so `\frac` and `\dfrac`, `x^2` and `x^{2}`, `(` and
`\left(` compare equal. Diffing LaTeX strings would report failures on correct
output and make the number meaningless.

**mean similarity** — edit distance over canonical leaf tokens, for triage. It
separates "missed a subscript" from "transcribed a different formula". Not for
publication; use `exact` for that.

**unparseable** — predictions that are not valid LaTeX at all. Tracked
separately because a backend that emits broken syntax fails differently from one
that misreads a symbol.

## Adding an entry

1. Crop one formula from a source page. Render at 2x; that is what the app sends.
2. Save it under `eval/dataset/images/` as `NNNN-short-name.png`.
3. Add `eval/dataset/NNNN-short-name.json`:

```json
{
  "id": "0002-ideal-gas-law",
  "image": "images/0002-ideal-gas-law.png",
  "category": "typeset",
  "latex": "PV = nRT",
  "speech": "P V equals n R T",
  "validated": { "by": "initials or role", "on": "2026-10-01" },
  "notes": "anything a future labeller needs to know"
}
```

4. `npm test` validates every entry at load. Ground truth that will not convert
   to MathML fails the suite, because a prediction scored against it would be
   meaningless.

### Categories

Backends diverge sharply by source material, so results are reported per
category rather than pooled.

| Category | What belongs in it |
| --- | --- |
| `typeset` | Clean single-column print. The easy case. |
| `dense` | Multi-column, tight leading, small subscripts, journal layout. |
| `handwritten` | Lecture notes, whiteboard photographs, exam scripts. |
| `chemistry` | Reaction equations, structural notation, state symbols. |

Aim for a spread rather than a round number. A set of 150 clean typeset formulas
says nothing about the cases that actually fail.

### Ground-truth conventions

- Transcribe what the page shows, not what it ought to show.
- Use the LaTeX a person would write: `x^{2}` over `x^2` for consistency, though
  the metric treats them as equal.
- Body only. No `$`, `$$`, `\[` or `\]` delimiters.
- One formula per image. Multi-formula pages belong to the page-level pipeline,
  not to this set.

### Validating the spoken form

`speech` starts as the ClearSpeak rendering the pipeline produces. It counts as
validated only once a screen-reader user has heard it in context and confirmed
they could follow it. Record who, and when, in `validated`.

Where their feedback disagrees with the rule set's output, that is a finding
about the rule set worth writing up — not a reason to hand-edit the expected
string.
